# Facts

- This goal is an orchestration goal: the agent plans, spawns workers, supervises, merges, verifies, documents, and commits instead of personally implementing the whole system in one thread.
- The goal is complete only when the full Dawn/Stealth end-state scope from AGENTS.md, CONTEXT.md, CONTEXT-MAP.md, docs/PRD.md, docs/work/IMPLEMENTATION-PRD.md, and docs/work/VERTICAL-SLICES.md is implemented with no required slice left incomplete.
- Milestone commits are allowed, but a milestone commit does not by itself satisfy the goal unless all required slices are complete.
- The orchestrator starts from the current clean committed baseline and preserves any later user changes instead of reverting or overwriting them.
- The orchestrator has high autonomy to create branches or worktrees, spawn Codex CLI workers, review and merge output, update docs, run checks, and commit verified units.
- The orchestrator stops for user input when work changes product scope, conflicts with an architecture non-negotiable, requires unavailable credentials or deployed infrastructure, or risks user changes.
- The startup sequence is ADR baseline verification or update first, then a transaction review tracer, then broader parallelization after shared contracts are stable.
- Business rules are implemented in packages/domain and packages/app; routes, UI components, workers, provider adapters, automations, and AI tools call application use cases instead of owning business logic.
- Postgres is the authoritative store for financial and operational state; Durable Objects, TanStack DB, KV, cache, search, vectors, and browser state are coordination layers, projections, or caches.
- Sensitive mutations enforce tenant isolation, permissions, idempotency, audit logging, and outbox event persistence before side effects run.
- Authoritative financial calculations use exact money semantics and never use JavaScript floating point for money totals, ledger state, invoices, payments, or reports.
- New product UI and component migrations use Coss UI primitives or particles, and workers read the repo-local Coss skill before writing Coss UI code.
- Worker prompts include the exact goal, relevant slices, authoritative docs, files or areas to inspect, acceptance criteria, verification commands, no ref/midday edits, no unrelated refactors, final summary format, and commit expectation.
- The orchestrator owns durable docs and ADR coherence, including docs/adr and docs/work/ORCHESTRATION.md; workers only propose docs changes or make narrow docs edits when explicitly assigned.
- External service work is implemented through provider boundaries, local or test adapters, schemas, fixtures, and verification harnesses before live credentials or deployments are required.
- The implementation posture is zero tech debt: touched areas move to the intended end-state architecture, unused compatibility paths are deleted when caller evidence supports removal, and speculative wrappers or fallback modes are avoided.
- Delivered behavior and stable contracts have relevant tests or verification; obsolete starter tests are updated or deleted instead of preserving compatibility coverage for removed paths.
- Worker output is not merged and milestone work is not committed until the orchestrator has inspected the diff, verified acceptance criteria, run relevant checks, and updated orchestration tracking.
- Partial foundation commits are allowed only when independently useful, verified, documented as partial, and not a regression for future slices.
- ref/midday is read-only reference material and is never edited by this goal.
