# Grill Notes

- Done boundary: Full end-to-end implementation of all required Dawn/Stealth slices, with verified commits and updated docs. Milestone commits are allowed, but the goal is not complete while any required slice remains incomplete.
- Orchestrator autonomy: High autonomy inside the documented architecture. The orchestrator may create worktrees/branches, spawn Codex CLI workers, review and merge output, update ADRs/docs, and commit verified units without asking at every step. It should stop for user input only when a decision changes product scope, violates an architectural non-negotiable, needs credentials/external services, or risks overwriting user changes.
- Git baseline: The working tree was clean after the user's commit. Treat the current commit as the baseline for orchestration and preserve any later user changes encountered during the goal.
- Documentation ownership: Durable docs and ADR updates stay centralized in the orchestrator. Workers may propose documentation updates or make narrow docs edits only when explicitly assigned, while the orchestrator owns `docs/adr/`, `docs/work/ORCHESTRATION.md`, and cross-slice context updates.
- External services: Implement provider boundaries, local/test adapters, schemas, use cases, and verification harnesses before requiring live credentials. Mark live wiring as blocked only where actual secrets, provider accounts, or deployed infrastructure are required. Prefer fake adapters, signed webhook fixtures, local queue/workflow shims, and production binding docs to keep progress moving.
- Architecture cleanup posture: Zero tech debt. When a slice touches a path, reshape it toward the intended end-state architecture instead of preserving starter compatibility or adding transitional cruft. Delete unused wrappers, fallback paths, bridge names, compatibility modes, and speculative abstractions when caller evidence supports removal. Preserve external contracts, persisted state, or public API compatibility only when there is a real caller or explicit requirement.
- Test posture: Tests are required for any delivered behavior or contract and should target the real final shape. Workers should add domain, use-case, API, job, sync, AI, or UI tests where their slice changes those contracts; avoid snapshot and implementation-detail tests; delete or update obsolete starter tests instead of retaining compatibility coverage for removed paths.
- Startup sequence: Require ADR baseline first, then transaction review tracer, then broader parallelization only after shared contracts and implementation patterns are stable enough to avoid merge and architecture drift.
- Milestone quality gate: Do not merge worker output or commit a milestone until the orchestrator has inspected the diff, verified acceptance criteria, run relevant checks, and updated orchestration tracking. Partial foundation commits are allowed only when independently useful, verified, documented as partial, and not a regression for future slices.
