# Grill Notes

- Done boundary: Full end-to-end implementation of all required Dawn slices, with verified commits or checkpoints and updated docs. Milestones are allowed, but the goal is not complete while any required slice remains incomplete.
- Implementation mode: The goal is now implementor-driven, not orchestrator-driven. The agent should personally implement the work in the active workspace and should not spawn Codex CLI workers, create worker worktrees, or delegate implementation unless the user explicitly asks later.
- Git baseline: Treat the current working tree as the baseline for the resumed implementation. Preserve user or prior-agent changes encountered during the goal.
- Documentation ownership: The implementing agent owns durable docs and ADR coherence, including `docs/adr/`, implementation tracking under `docs/work`, and cross-slice context updates.
- External services: Implement provider boundaries, local/test adapters, schemas, use cases, and verification harnesses before requiring live credentials. Mark live wiring as blocked only where actual secrets, provider accounts, or deployed infrastructure are required. Prefer fake adapters, signed webhook fixtures, local queue/workflow shims, and production binding docs to keep progress moving.
- Architecture cleanup posture: Zero tech debt. When a slice touches a path, reshape it toward the intended end-state architecture instead of preserving starter compatibility or adding transitional cruft. Delete unused wrappers, fallback paths, bridge names, compatibility modes, and speculative abstractions when caller evidence supports removal. Preserve external contracts, persisted state, or public API compatibility only when there is a real caller or explicit requirement.
- Test posture: Tests are required for any delivered behavior or contract and should target the real final shape. Add domain, use-case, API, job, sync, AI, or UI tests where a slice changes those contracts; avoid snapshot and implementation-detail tests; delete or update obsolete starter tests instead of retaining compatibility coverage for removed paths.
- Startup sequence: Require ADR baseline verification first, then transaction review tracer completion, then the remaining vertical slices in dependency order.
- Milestone quality gate: Do not commit a milestone until the agent has inspected the diff, verified acceptance criteria, run relevant checks, and updated implementation tracking. Partial foundation commits are allowed only when independently useful, verified, documented as partial, and not a regression for future slices.
